# 医疗研究 Agent 本地备份恢复运维手册

> 版本：1.0
>
> 日期：2026-07-29
>
> 适用范围：当前 Windows 单节点集成环境

## 1. 目的与边界

本手册用于备份和验证以下成对恢复的数据：

- PostgreSQL `medical_agent`：身份、医院、课题、文件元数据、Agent、证据、审核和导出记录。
- MinIO `medical-agent-files`：上传文件、原始科研 API 响应、模板和导出文档。

脚本不备份 DeepSeek Token、数据库密码、MinIO 明文密钥、日志、JDK、ClamAV 病毒库或前端
构建目录。MinIO 凭据只从本机 DPAPI 文件读入进程内存，并通过临时环境变量提供给官方
MinIO Client；不会写入恢复点、manifest 或普通日志。

这是一套经过实机验证的本地基线，不等同于生产灾备。当前没有异地副本、备份加密、不可变
存储、自动保留清理、恢复审批或 RPO/RTO 承诺。

## 2. 工具与目录

| 项目 | 当前路径或版本 |
| --- | --- |
| PostgreSQL 工具 | `D:\develop\postgresql18\bin` |
| MinIO Client | `D:\develop\minio\mc.exe`，RELEASE.2025-08-13T08-35-41Z |
| MinIO DPAPI 凭据 | `D:\develop\minio\.medical-agent-credential.xml` |
| 恢复点根目录 | `artifacts\backups`，已加入 `.gitignore` |
| 运行临时目录 | `artifacts\runtime` |

每个恢复点包含：

```text
{backup-id}/
├─ database.dump
├─ objects/
├─ backup-metadata.json
└─ manifest.sha256.json
```

`database.dump` 是 PostgreSQL custom archive。元数据保存逻辑库/桶名、逐表行数、对象数量和
总字节数，不保存连接密码。manifest 保存每个文件的相对路径、字节数和 SHA-256。

## 3. 创建一致恢复点

### 3.1 变更前检查

```powershell
Set-Location D:\develop\AIWorkspace\MEDICAL_AGENT
.\tools\status-local.ps1
```

确认 PostgreSQL 和 MinIO 为 `UP`。通知当前使用者进入短暂停写窗口。

### 3.2 停止后端写入

```powershell
.\tools\stop-local-backend.ps1
```

脚本只停止 8080 上命令行包含本项目 JAR 的 Java 进程。再次确认 8080 不再监听。不要停止
PostgreSQL 或 MinIO，否则无法生成逻辑备份。

### 3.3 创建恢复点

```powershell
$backup = .\tools\backup-local.ps1 -Label recovery-point
$backup | Format-List
```

后端仍运行时脚本会拒绝继续。虽然存在 `-AllowOnline`，但在线模式不保证 PostgreSQL 与 MinIO
的共同时间点，只可用于明确接受风险的临时副本。

### 3.4 独立校验

```powershell
.\tools\verify-local-backup.ps1 -BackupDirectory $backup.Directory
```

校验包括：

1. 元数据和 manifest Schema/备份 ID 一致。
2. manifest 相对路径不能逃逸恢复点目录。
3. 全部文件的长度和 SHA-256 一致。
4. `pg_restore --list` 可以读取数据库归档。
5. 本地对象数量和字节数与备份元数据一致。

只有返回 `Status=Valid` 才能把目录登记为有效恢复点。

### 3.5 恢复服务

```powershell
.\tools\start-local-backend.ps1
.\tools\status-local.ps1
.\tools\smoke-local.ps1
```

状态必须全部为 `UP`，冒烟必须 8/8 通过。若失败，保留后端日志和恢复点，不要删除最近一次
已知有效恢复点。

## 4. 恢复到隔离的新目标

恢复脚本故意不支持覆盖现有数据库或桶。目标必须不存在并满足：

- 数据库：`medical_agent_restore_*`
- 存储桶：`medical-agent-restore-*`

示例：

```powershell
.\tools\restore-local-backup.ps1 `
  -BackupDirectory 'D:\develop\AIWorkspace\MEDICAL_AGENT\artifacts\backups\{backup-id}' `
  -TargetDatabase 'medical_agent_restore_manual01' `
  -TargetBucket 'medical-agent-restore-manual01'
```

执行顺序：

1. 先执行完整只读校验。
2. 确认数据库和桶均不存在。
3. 创建由 `medical_agent` 所有的新数据库。
4. 管理员预装 pgvector；恢复清单跳过扩展创建/注释。
5. 由 `medical_agent` 恢复业务 Schema 和数据。
6. 创建新桶并恢复对象。
7. 逐表比对精确行数。
8. 比对对象数量和字节数。
9. 重新下载恢复对象并逐个比对 SHA-256。

任一步失败都会返回非零结果。恢复脚本不会自动删除失败目标，以便调查；删除必须由运维人员
核对安全前缀和实际目标后单独执行。

## 5. 自动恢复演练

```powershell
.\tools\stop-local-backend.ps1
.\tools\exercise-backup-restore.ps1
.\tools\start-local-backend.ps1
.\tools\smoke-local.ps1
```

演练创建随机临时源桶，写入一个 `SYNTHETIC_ANONYMOUS` 文本对象，备份当前数据库和该桶，
再恢复到随机新数据库/桶。成功后清理：

- `medical_agent_restore_*` 临时数据库；
- `medical-agent-backup-source-*` 临时源桶；
- `medical-agent-restore-*` 临时目标桶；
- `artifacts\runtime\backup-exercise-*` 临时文件。

演练恢复点保留在已忽略的 `artifacts\backups`，用于留证和排错。

## 6. 正式切换原则

本地脚本不直接覆盖正式目标。发生恢复需求时应：

1. 冻结写入并保全当前故障现场。
2. 选择最近一个 manifest 校验通过的恢复点。
3. 恢复到隔离的新数据库和新桶。
4. 执行业务抽样、权限隔离、文件下载和完整冒烟。
5. 通过受控配置变更切换数据库 URL 和桶名。
6. 保留旧目标直到回滚窗口结束。
7. 记录恢复点 ID、操作人、时间、校验结果和切换决定。

生产环境还必须验证应用角色权限、对象桶策略、TLS、密钥注入、审计以及外部依赖配置。

## 7. 保留与安全建议

在医院批准正式策略前，脚本不自动删除恢复点。建议评审以下基线：

- 日备份保留 7 份、周备份 4 份、月备份 12 份；
- 至少一份加密的异地或离线副本；
- 恢复目录使用最小文件权限和加密卷；
- 删除使用双人复核，并确认至少仍有一份已演练的有效恢复点；
- 每月执行一次隔离恢复，每季度记录一次完整灾难恢复演练；
- 任何包含真实医院数据的恢复点不得进入 Git、聊天、工单附件或普通共享盘。

## 8. 常见故障

| 现象 | 处理 |
| --- | --- |
| `Backend is running` | 正常安全门；先停止后端，或明确接受风险后使用在线开关 |
| `checksum mismatch` | 恢复点损坏；停止使用并核对传输/磁盘，不要修改 manifest |
| `pg_restore --list` 失败 | 数据库归档不完整或版本不兼容 |
| 目标已存在 | 使用新的安全前缀目标；脚本不会覆盖 |
| pgvector 创建失败 | 确认管理员具备扩展权限且 PostgreSQL 已安装 pgvector |
| MinIO mirror 数量不一致 | 检查写入是否真正冻结、桶策略和磁盘空间 |
| 恢复后冒烟失败 | 不切换；保留新旧目标和日志，按 Trace ID 调查 |
