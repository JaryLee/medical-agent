## 2. 完成范围

### 2.1 方向与 Prompt

- STEP04 使用独立版本化 Prompt，不再复用 STEP01。
- 每次方向生成保存候选集 ID、Schema 版本、完整快照和内容哈希。
- STEP05 同时校验候选集、候选 ID 和哈希，拒绝不存在、过期或被篡改的确认。
- STEP06 只消费医生确认的完整快照，不重新生成研究方向。
- Prototype 根路径默认关闭，不能绕过持久化工作流。

### 2.2 模型调用审计与保留

- V20 新增 `ai_model_call_log`，模型调用开始前创建真实调用 ID。
- 记录医院、课题、任务、步骤、尝试号、Provider、模型、Prompt/Schema 版本、输入输出哈希、
  路由理由、安全检查结果、结束原因、耗时、状态和错误摘要。
- 脱敏输入快照保存 Prompt 模板/哈希、受控输入哈希及数据库重放引用，不保存原始研究想法。
- 输出保存受控结构化结果；失败信息统一脱敏，不把供应商原始错误或敏感负载写入审计库。
- 默认保留期限为负载 90 天、元数据 3 年；定时批次只处理非 `REQUESTED` 记录。
- 数据库快照到期后置空并记录销毁时间；元数据到期时在同一 SQL 边界解除步骤引用后删除。
- 带私有对象键的记录不会只清数据库引用，而是失败关闭并告警，等待对象存储销毁流程。
- 完整原始负载默认不保存；只有独立加密私有对象存储和审批访问流程就绪后才允许启用。

### 2.3 租约、围栏和原子提交

- V21 新增步骤尝试表、`execution_token`、租约所有者、领取时间、心跳和当前尝试 ID。
- `claimNext` 使用事务与 `FOR UPDATE SKIP LOCKED`，同一任务同一时刻只能被一个 Worker 领取。
- 默认租约 45 秒、心跳 10 秒，并在启动时校验心跳必须显著短于租约。
- 所有新 Worker 完成/失败写入都携带 ClaimHandle；旧 token 返回 `STALE_TOKEN`。
- 心跳同时更新任务和步骤尝试；尝试不匹配时抛错，使整个事务回滚。
- V22 将任务、尝试、步骤和事件放在一个事务提交边界，SSE 仅在提交后发布。
- 事件使用稳定唯一键；重复提交返回已提交结果，不重复发布领域结果。
- 取消和超时会关闭当前尝试、清除执行令牌并留下稳定事件。

### 2.4 外部工具幂等

- V23 新增工具调用账本和稳定 operation key。
- 同一逻辑操作的 `RUNNING`/`COMPLETED` 记录受数据库单活唯一约束保护。
- 已完成调用在任务重领后复用原结果，不再次访问外部工具。
- 旧尝试仍在执行或调用结果未知时失败关闭，不自动重复外部副作用。

### 2.5 CI 门禁

- CI 使用真实 PostgreSQL 与 pgvector 服务。
- Flyway 和关键 PostgreSQL 测试被显式要求运行，缺少数据库条件时构建失败，而不是静默跳过。
- P0-A 的空库迁移、V19 升级和并发/事务专项测试纳入后端 `verify`。

## 3. Review 发现及修复

| 级别 | 发现 | 修复与证据 |
| --- | --- | --- |
| P1 | 不同重领尝试可能并发执行同一稳定外部工具操作 | V23 对 `RUNNING`/`COMPLETED` 建立单活唯一约束；JDBC 与内存仓储均失败关闭；内存和真实 PG 测试通过 |
| P1 | 任务心跳成功而步骤尝试心跳失败时可能半提交 | 尝试更新不为 1 时在事务内抛错；真实 PG 回归证明任务租约整体回滚 |
| P1 | 任务、步骤、尝试和事件分散写入可能形成部分结果 | V22 原子提交；非法事件写入回归证明全部回滚 |
| P1 | 旧 Worker 可能在租约丢失后覆盖新结果 | execution token、当前尝试 ID 和步骤条件共同围栏；旧 token 返回 `STALE_TOKEN` |
| P1 | 只缓存 `COMPLETED` 工具结果不能阻止在途重复调用 | 单活 operation 约束覆盖 `RUNNING` 和 `COMPLETED` |
| P1 | 模型审计只有哈希，不能重放实际上下文 | 增加 Prompt/渲染哈希、受控输入引用、路由、安全结论和完整受控输出快照 |
| P1 | 真实 PostgreSQL 测试可能因环境缺失而跳过 | CI 强制 PostgreSQL/pgvector 并显式启用 live gate |
| P1 | 只有保留期限字段，没有可执行清理边界 | 增加定时批次、对象键失败关闭、内存与真实 PG 清理测试 |

修复后的工作树逐文件复核未发现可成立的遗留安全问题；P0-B 负责的租户复合外键、身份规范化
和审核角色分离没有被误报为 P0-A 已完成。

## 5. 发布与回退

当前旧应用与 V22 之后的事件写入结构不兼容，禁止混合部署。发布顺序固定为：

1. 停止旧 Worker/后端；
2. 确认不存在 `RUNNING` Agent 任务；
3. 完成数据库与对象存储备份；
4. 重跑跨医院关系、重复值和迁移风险只读扫描；
5. 使用新版本迁移制品依次执行 V20～V23；
6. 核对 Flyway、关键约束、历史回填和表计数；
7. 启动新后端，再启动前端；
8. 执行认证、创建任务、确认、重试、取消、SSE 和保留任务冒烟。

如果迁移前仍存在 `RUNNING` 任务，V21 应失败关闭。此时不得强行修改状态或删除数据，必须停留在
V19，查明任务归属并由负责人确认处置方式。
