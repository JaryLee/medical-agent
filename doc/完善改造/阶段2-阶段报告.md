## 2. 主要交付

### 2.1 V27 项目工作区基础设施

- `project_workspace_cursor` 保存医院/课题范围的单调读模型版本；
- `project_read_model_event` 保存可按事件 ID 补发的项目级更新通知；
- `project_workspace_command` 保存动作、请求哈希、操作者、预期版本和结果，用于安全重放；
- 课题创建、名称更新和 Agent 领域事件通过触发器推进版本并写入更新事件；
- 命令预留对项目游标行加锁，确保两个并发动作不能同时消费相同 `If-Match` 版本；
- 幂等键在同一医院、课题和操作者内跨动作唯一；同键不同动作或不同负载均拒绝。

V27 只增不删，不改写现有任务负载。当前正在运行的 V19 数据库和应用保持原状。

### 2.2 后端业务读模型和 API

新建 `com.jarylee.medicalagent.workspace` 包，完成：

- 课题列表、工作区摘要、九阶段导航、用户/课题待办和构想方向详情；
- 研究构想启动、澄清提交、方向确认、取消和重试统一动作端点；
- 项目级 SSE、`Last-Event-ID` 补发、旧版本拒绝和需要全量重同步信号；
- SQL 层医院/成员过滤、项目 key 防枚举和动作端点 RBAC；
- 面向医生的稳定中文状态、阶段、下一动作、阻塞原因和不透明待办 key。

V2 普通响应、URL 和 SSE 不返回内部 UUID、任务 ID、`STEP_*` 或原始模型负载。

## 3. 契约与安全边界

- 动作必须携带 16～128 字符 `Idempotency-Key` 和 `If-Match: "rmv-N"`；
- 服务端每次重新执行身份、医院、成员角色和领域状态校验；
- 非成员、跨院、非法或未知 `projectKey` 统一按防枚举边界处理；
- VIEWER 可读取但不能执行写动作；
- 待办查询当前只开放 `OPEN`，不接受客户端借状态参数扩大读取范围；
- 本地草稿只保存构想/澄清文本，不保存凭据、内部标识或模型原始负载；
- 当前 V19 运行应用没有被新迁移或新代码干扰。
