## 3. 当前覆盖缺口

1. 默认后端 94 个测试中有 12 个按环境跳过；当前 CI 不能证明真实 PostgreSQL、迁移、医院
   隔离和多 Worker 并发。
2. `FlywayMigrationTest` 在没有 Docker 时跳过。已有本地空库测试作为补证，但 CI 必须提供
   PostgreSQL 服务或 Testcontainers。
3. 默认 Playwright 通过 mock 路由验证主要流程，真实 DeepSeek 只在显式授权和密钥可用时运行。
4. 真实 PostgreSQL API 全链路会写当前库和对象存储，虽有清理逻辑，但尚未成为隔离临时库中的
   必跑门禁。
5. 现有 Agent 测试主要验证顺序执行，不能证明执行令牌 fencing、心跳、双 Worker 抢占、租约
   失效后旧 Worker 禁写和工具调用去重。
6. 缺少工作台 V2 契约、功能开关、旧版回退和 SSE 重连版本冲突测试。

## 4. 分级缺陷

- `P0`：跨医院泄露、敏感数据外发、越权下载、错误的医学/统计结论被标记为正式批准、数据损坏。
- `P1`：重复模型/工具调用产生不一致、租约丢失后覆盖、任务无法恢复、错误导出版本、核心流程
  不可用。
- `P2`：性能、可用性、可观测性和非核心交互问题。

阶段门禁存在任何未解决 P0/P1 时必须 `BLOCKED`。

## 5. 阶段通用门禁

每阶段至少通过：

1. 后端全量 `verify`，0 失败/错误；
2. 前端 lint、typecheck、Vitest、build，0 失败；
3. 与本阶段有关的 Playwright 场景；
4. 从空库执行全部 Flyway；
5. 从 V19 生产形态副本升级到最新迁移；
6. 真实 PostgreSQL 正向、错误和并发场景；
7. 两医院隔离负向测试；
8. 修改过的权限、导出、模型出站和对象存储安全测试；
9. 独立复核后无 P0/P1；
10. 回退路径实际验证。

“按条件跳过”只能用于外部供应商联机测试、真实专家/真实模板等明确外部条件；数据库迁移、
医院隔离、并发和幂等测试不得跳过。

## 6. 阶段专属硬门禁

### P0-A：可信执行

- STEP04 使用自己的 Prompt；方向候选只生成一次，确认绑定候选集版本和哈希；
- 模型调用在发起前生成稳定 ID，输入/输出审计可关联；
- 两个 Worker 只有一个获得同一执行令牌；
- 心跳默认 10 秒，租约默认 45 秒，配置校验要求心跳小于租约三分之一；
- 旧令牌对完成、失败、等待、重排队均返回 `STALE_TOKEN` 且不能改变当前任务；
- 崩溃重启不重复已成功的外部工具调用。

### P0-B：身份与医院隔离

- 不可枚举 `projectKey`；
- 组合外键阻止跨医院挂接；
- 两医院同名用户/课题/文件场景全部隔离；
- 普通响应和 URL 不泄露内部 UUID。

### 阶段 2～6

- 每个纵向切片同时具有读模型、命令幂等、授权、审计、真实 PostgreSQL、E2E 和旧版回退证据；
- 草案导出必须验证三方审核矩阵、内容哈希和免责声明；
- 任何页面不得出现“已获伦理/正式批准”的误导表述。

## 7. CI 改造验收

P0-A 结束前，CI 应：

- 使用固定 Java 21、Node LTS/受支持版本和 PostgreSQL 版本；
- 启动 PostgreSQL + pgvector，真实运行迁移、仓储、隔离和并发测试；
- 把必需测试的假跳过视为失败；
- 保存 Surefire、Playwright、覆盖率、迁移和前端构建报告；
- 对 Maven/Node 依赖做缓存，但不缓存数据库或测试结果；
- 不把 DeepSeek、MinIO 或数据库密钥写入日志。
