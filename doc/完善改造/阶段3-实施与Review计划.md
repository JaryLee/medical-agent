## 1. 目标

第三阶段把证据、研究设计、方案、统计、质量、三方审核和科研草案导出从旧任务 UUID/完整
`outputJson` 页面迁入工作区 V2，并在迁移过程中提取对应后端适配器、公开 DTO、前端类型和组件。

退出时必须达到：

1. 七个剩余阶段都有独立 V2 读模型、页面、加载/空/错误/冲突状态和服务端授权；
2. 检索策略确认、设计确认、方案修订、医学/统计审核、负责人确认和导出均通过统一工作区动作；
3. 页面与普通响应不含任务、方案、章节、审核、模板、引用格式或导出记录的内部 UUID；
4. 方案章节具有稳定公开 key、人工修订版本、历史和比较；修订后旧审核必须失效；
5. 三方审核按医学、统计、负责人三个不同账号和当前内容哈希硬校验；
6. 导出只允许锁定且三方通过的当前内容，并始终包含科研草案免责声明；
7. V2 默认关闭，旧版回退保持可用；旧 UUID API 不删除；
8. 后端、真实 PostgreSQL、两医院、契约、前端、E2E、可访问性和 Bundle 门禁通过；
9. Review 后无遗留 P0/P1。

## 3. 冻结的公开契约

### 3.1 只读端点

- `GET /api/research/projects/{projectKey}/evidence`
- `GET /api/research/projects/{projectKey}/design`
- `GET /api/research/projects/{projectKey}/protocol`
- `GET /api/research/projects/{projectKey}/statistics`
- `GET /api/research/projects/{projectKey}/quality`
- `GET /api/research/projects/{projectKey}/internal-review`
- `GET /api/research/projects/{projectKey}/draft-export`
- `GET /api/research/projects/{projectKey}/exports/{exportKey}/download`

所有 JSON 继续使用第二阶段 `Envelope(data,meta)`；下载端点返回受鉴权的 DOCX。公开资源使用
`evi_`、`sec_`、`chk_`、`tpl_`、`style_`、`exp_` 等由当前课题事实和内部标识生成的不透明稳定
key，服务端按当前课题重新解析，禁止客户端提交 UUID。

### 3.2 新增统一动作

- `CONFIRM_SEARCH_STRATEGY`
- `CONFIRM_OBSERVATIONAL_DESIGN`
- `UPDATE_PROTOCOL_SECTION`
- `REGENERATE_PROTOCOL_SECTION`
- `SUBMIT_PROTOCOL_REVISION`
- `ADD_INTERNAL_REVIEW_COMMENT`
- `SUBMIT_MEDICAL_REVIEW`
- `SUBMIT_STATISTICAL_REVIEW`
- `CONFIRM_INTERNAL_REVIEW`
- `EXPORT_RESEARCH_DRAFT`

动作沿用 16～128 字符 `Idempotency-Key`、跨动作唯一范围和
`If-Match: "rmv-N"`。需要内部乐观版本的操作在 body 中只接受公开业务版本号；服务端把
公开 key 映射为当前医院/课题下的内部实体，再调用唯一领域服务。

### 3.3 公开状态和免责声明

- 研究类型只开放横断面、队列、病例对照；
- 证据明确区分文献元数据、注册记录、摘要级依据和待专家确认，不把相似度当创新性证明；
- 统计参数缺失保持 `NEEDS_INPUT` 并阻断确定性样本量结论；
- STROBE 是报告完整性预检查，不是研究质量评分；
- 审核只称“内部医学/统计/负责人确认”，不表达伦理或正式批准；
- 导出名称、正文、页眉/页脚和文档属性继续保留“科研草案”边界。

## 4. 实施切片

### S3-A：公共 artifact 适配层

- 新建工作区 artifact DTO、稳定 key 解析、状态中文字典和聚合服务；
- 只从当前医院、当前课题最新任务及独立领域事实源构造 DTO；

- 扩展阶段动作和待办映射，使已迁移阶段不再指向旧版。

### S3-B：证据切片

- 展示已确认/待确认检索策略、PubMed、注册研究、Crossref 核验和相似研究；
- PMID、DOI、NCT ID 作为医学来源标识保留，内部检索记录 UUID 不返回；
- V2 确认检索式后调用现有唯一工作流服务；
- 页面展示来源、验证状态、覆盖范围、限制和官方链接。

### S3-C：研究设计切片

- 展示三种观察性设计的适用条件、可行性、缺失项、偏倚和替代方案；
- V2 只允许三种已冻结研究类型；
- 确认主要结局并明确授权后才进入方案生成。

### S3-D：方案和版本切片

- 展示 18 个稳定章节及当前版本；
- 支持人工修订、确定性章节重生成、版本历史和相邻/指定版本比较；
- 章节追加版本采用数据库乐观锁和医院组合约束；
- 修订后更新当前任务方案快照，清除下游派生快照，重新排队质量链并使旧审核失效；
- 已锁定章节不可修改，语义未变化不得制造空版本。

### S3-E：统计与质量切片

- 展示统计计划、缺失样本量参数、主张—引用和 STROBE 22 项；
- 公开稳定章节/检查项 key，不返回 claim/link/check/task UUID；
- 页面不生成样本量结论，不把摘要证据提升为全文支持；
- 质量问题可直接定位到对应方案章节。

### S3-F：三方审核切片

- 公开审核轮次、医学/统计各自决定、负责人确认、批注和不可变历史；
- 批注通过 `sectionKey + versionNo` 或 `checkItemKey` 锚定；
- 医学与统计由两个不同 EXPERT 账号执行，且都不能是课题负责人；
- 两者通过后才允许课题负责人确认；任一退回必须有本轮可定位批注；
- 内容哈希变化后旧轮次自动失效。

### S3-G：导出切片

- 只列出本院已发布模板和引用格式，并以不透明 key 暴露；
- 课题负责人明确确认当前锁定审核内容后才执行受控 DOCX 导出；
- 下载按项目 key + 导出 key 重新鉴权并校验对象路径和 SHA-256；
- 正式方案导出继续在产品层硬禁用。

### S3-H：前端结构提取

- 新建 `workspaceArtifacts` API/类型/状态模块；
- 分别建立 Evidence、Design、Protocol、Statistics、Quality、Review、Export 组件；
- V2 页面按 section 懒加载对应组件，不引用旧 `platform.ts` 类型；
- 所有动作处理版本冲突后刷新，SSE 只触发重新获取；
- 保留加载、空、失败、冲突、离线、只读和固定旧版回退状态。
