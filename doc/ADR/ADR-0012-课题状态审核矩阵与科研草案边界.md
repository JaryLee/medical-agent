# ADR-0012：课题状态、审核矩阵与科研草案边界

- 状态：已接受
- 日期：2026-07-30
- 适用范围：匿名医疗科研课题首个技术试点

## 背景

当前系统已有 Agent 任务状态、专家审核和 DOCX 导出，但页面仍可能从 `STEP_*` 和任务输出
推断业务进度，“已批准”也容易被误解为已获伦理或科研管理审批。进入工作台改造前，必须冻结
业务状态、审核职责、内容变更后的失效规则和导出边界。

## 决策

### 1. 试点输出只允许“科研草案”

首个试点不产生“正式方案”“已批准方案”或任何暗示伦理、科研管理、临床实施授权的输出。
所有可下载文件的封面、页眉或首页醒目区域，以及 OOXML 文件属性，均须包含：

> 仅供科研设计讨论，未经伦理和科研管理审批

系统中的 `APPROVED` 只表示“科研草案内部审核完成”。中文界面必须显示完整含义，不得只显示
“已批准”。伦理审批、科研管理审批、研究注册和临床执行授权均是系统外要求。

### 2. 首批研究类型

试点只开放：

- `CROSS_SECTIONAL`：横断面研究；
- `COHORT`：队列研究；
- `CASE_CONTROL`：病例对照研究。

其他研究类型可以作为将来扩展项保留在代码枚举中，但不得在试点页面创建、推荐或导出。

### 3. 课题业务状态

| 代码 | 中文含义 | 进入条件 | 允许离开方向 |
| --- | --- | --- | --- |
| `DRAFT` | 草稿 | 课题已创建，尚未启动工作流 | `IN_PROGRESS`、`ARCHIVED` |
| `IN_PROGRESS` | 编制中 | Agent 或用户正在完善内容 | `WAITING_REVIEW`、`FAILED`、`ARCHIVED` |
| `WAITING_REVIEW` | 等待内部审核 | 医学和统计审核材料已冻结 | `REVISION_REQUIRED`、`APPROVED`、`ARCHIVED` |
| `REVISION_REQUIRED` | 需修订 | 任一审核角色退回 | `IN_PROGRESS`、`ARCHIVED` |
| `APPROVED` | 科研草案内部审核完成 | 医学、统计审核均通过且负责人确认 | `COMPLETED`、`REVISION_REQUIRED`、`ARCHIVED` |
| `COMPLETED` | 科研草案已受控导出 | 草案导出成功且哈希、版本已记录 | `ARCHIVED` |
| `ARCHIVED` | 已归档 | 负责人执行归档 | 无常规迁移 |
| `FAILED` | 系统处理失败 | 不可自动恢复的技术失败 | `IN_PROGRESS`、`ARCHIVED` |

状态转换由后端领域服务校验并写审计。前端不得直接提交任意目标状态，也不得从任务步骤自行计算。

### 4. Agent 任务状态

继续使用：

`QUEUED`、`RUNNING`、`WAITING_CONFIRMATION`、`REVISION_REQUIRED`、`COMPLETED`、
`FAILED`、`CANCELLED`。

它们是技术执行状态，不等同于课题业务状态。课题摘要由后端聚合两类状态，并返回下一动作和阻塞
原因。

### 5. 阶段读模型状态

页面阶段只使用：

`NOT_STARTED`、`AVAILABLE`、`IN_PROGRESS`、`WAITING_USER`、`WAITING_REVIEW`、
`BLOCKED`、`COMPLETED`、`FAILED`。

阶段代码冻结为：

`PROJECT_SETUP`、`RESEARCH_IDEA`、`RESEARCH_DIRECTION`、`EVIDENCE`、
`STUDY_DESIGN`、`PROTOCOL`、`STATISTICS`、`QUALITY`、`REVIEW`、
`DRAFT_EXPORT`、`COMPLETED`。

### 6. 审核角色与状态

审核职责必须分别完成：

| 职责 | 责任人 | 最小检查范围 | 可否代替其他职责 |
| --- | --- | --- | --- |
| 医学审核 | 医学专家 | 临床问题、纳排标准、结局、医学合理性、风险表述 | 否 |
| 统计审核 | 统计专家 | 设计、偏倚、样本量、变量、分析方法、缺失数据 | 否 |
| 负责人确认 | 课题负责人 | 接受两类审核意见，确认草案版本和导出 | 否 |

默认要求三项职责由三个独立账号完成。课题负责人不得审核自己提交的医学或统计意见。只有医院
明确形成例外政策并新增 ADR，才可调整人员独立性要求。

审核任务状态冻结为：

`PENDING`、`IN_REVIEW`、`APPROVED`、`REVISION_REQUIRED`、`SUPERSEDED`、
`CANCELLED`。

### 7. 审核轮次与失效

- 送审时创建不可变的内容版本和审核轮次。
- 任一医学或统计审核退回，本轮不能再进入负责人确认。
- 被审核内容发生语义变化时，当前两类审核和负责人确认全部标记为 `SUPERSEDED`，修订后创建
  新轮次。
- 只改变受控模板、引用显示样式、分页等不影响语义的格式变更，不使内容审核失效，但必须生成
  新导出版本、哈希和审计记录。
- 负责人确认后、导出前若内容哈希变化，导出必须阻断。

### 8. 导出矩阵

| 医学审核 | 统计审核 | 负责人确认 | 科研草案导出 | 正式方案导出 |
| --- | --- | --- | --- | --- |
| 未通过 | 任意 | 任意 | 禁止 | 禁止 |
| 通过 | 未通过 | 任意 | 禁止 | 禁止 |
| 通过 | 通过 | 未确认 | 禁止 | 禁止 |
| 通过 | 通过 | 已确认且内容哈希一致 | 允许 | 禁止 |

## 模型调用审计与保留

数据库保存模型调用元数据、输入/输出哈希、Schema/Prompt/模型版本、脱敏结构化快照、调用结果和
关联的任务/步骤尝试。原始完整输入与输出只保存在医院私有的加密对象存储中，不进入普通日志。

在医院正式数据政策另有更严格要求前，采用以下默认值：

- 原始完整负载保留 90 天后自动销毁；
- 数据库审计元数据、哈希和脱敏结构化快照保留 3 年；
- 优先选择供应商零保留；若无法零保留，供应商侧最长 30 天；
- 合法留置必须有明确范围、期限和审批记录。

普通管理员只能查看元数据和脱敏快照。解密完整负载需要安全审计权限、双人审批、限定原因和
时效，并对申请、读取、下载和失败尝试全部留痕。医院政策可以缩短保留期；延长或扩大访问范围
必须新增 ADR。

## 后果

- 页面和 API 必须明确区分业务状态、技术任务状态和阶段状态。
- 既有“正式导出”文案与入口在迁移完成前必须由功能开关隔离。
- 后续迁移需要保存既有审核历史，不自动把历史记录解释为本 ADR 下的内部审核完成。
- 本决策不代表医学、统计、伦理或科研管理专家已经对具体课题作出专业批准。
