# ADR-0010：健康检查采用最小匿名暴露

- 状态：已接受
- 日期：2026-07-29

## 背景

本地联调、反向代理和未来编排平台需要无需业务会话即可判断应用是否存活和是否具备完整服务
能力。健康响应如果包含组件名称、地址、异常或配置，会向未认证访问者泄露内部拓扑；如果将
全部 Actuator 端点匿名开放，风险更高。

## 决策

应用引入 Spring Boot Actuator，但 Web 层只暴露 `health`。安全过滤链只匿名放行：

- `GET /actuator/health`
- `GET /actuator/health/liveness`
- `GET /actuator/health/readiness`

健康端点统一设置 `show-details=never` 和 `show-components=never`。响应只提供整体状态，
不包含组件名、主机、端口、凭据或异常。

总健康 `/actuator/health` 是深度检查：使用框架数据库探针、对象存储桶可达性探针，以及
`FILE_SCAN_MODE=clamav` 时的 clamd `PING/PONG` 探针。对象存储或 ClamAV 不可用时只返回
整体 `DOWN`，探针实现本身也不附加异常详情。`liveness` 和 `readiness` 保留 Spring
ApplicationAvailability 的进程状态语义，不代替总健康的依赖检查。

`env`、`configprops`、`beans` 等其他 Actuator 端点不暴露，且安全过滤链不会匿名放行
`/actuator/**`。

## 后果

- 反向代理和本地运维脚本可使用总健康执行启动门禁和完整依赖验收。
- 存活探针不会因外部依赖短暂不可用触发进程重启风暴。
- 匿名调用者只能获知整体 UP/DOWN，这一位运行状态信息是可用性探测所必需的最小披露。
- 指标、告警、集中日志和分布式追踪仍需后续单独设计，不能通过扩大匿名 Actuator 暴露解决。

## 验证

`ProductionSecurityConfigurationTest` 验证匿名存活/就绪探针可访问且不包含组件详情，同时
`/actuator/env` 返回 403。ClamAV 与对象存储健康指示器具有独立单元测试；本机
`status-local.ps1` 和 `smoke-local.ps1` 已对 PostgreSQL、MinIO、ClamAV 和新版后端完成
真实闭环验证。
